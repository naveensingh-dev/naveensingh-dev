## What makes this GitHub different

### 1. Portfolio, not storage
Each visible repository is intended to represent a capability area: architecture, frontend systems, AI workflows, product quality, or automation.

### 2. Systems thinking over noise
I prefer fewer high-signal repositories over dozens of shallow experiments.

### 3. Public + private depth
The public projects show execution style; the private work reflects deeper real-world complexity, architecture tradeoffs, and product delivery maturity.

### 4. Engineering with narrative
I care about how work is presented: README quality, demos, structure, and decision clarity matter as much as the code itself.
